# How we work on GitHub

1. **Every task is a GitHub Issue.** Take one by assigning yourself.
2. **One branch per issue**, e.g. `12-parser-days`. Never commit directly to `main`.
   - New to Git? Use **GitHub Desktop** or the Source Control panel in VS Code: no command line needed.
3. **Pull `main` before you start** each day, so you work on the latest version.
4. **Small pull requests**: one task each. The team's integrator reviews and merges (backup: repo owner).
5. **Done means:** works in laptop Chrome **and** on the iPad · no errors in the console · tests pass · a screenshot in the pull request.
6. AI-assisted code is fine, but whoever opens the pull request must be able to explain it.
7. **Changing the Bluetooth messages?** Update [protocol.md](protocol.md) first, reviewed by one person from each team.
